# PageTracker REST API

Цей документ допомагає почати роботу з API та знаходити потрібні операції.
Повний контракт запитів, схем, відповідей і статусів визначає
[OpenAPI 3.1 YAML](../spec/openapi.yaml); еквівалентний JSON доступний у
[openapi.json](../spec/openapi.json). Якщо короткий опис нижче розходиться з
OpenAPI, джерелом істини є специфікація.

## Підключення та сесія

API має базовий шлях `/api` і працює на тому самому origin, що й вебзастосунок.
Для локального запуску це, наприклад, `http://127.0.0.1:4179/api`.

1. Створіть обліковий запис через `POST /api/auth/register`. Реєстрація не
   виконує вхід автоматично.
2. Увійдіть через `POST /api/auth/login`. Успішна відповідь встановлює cookie
   `pt_session` з атрибутами `HttpOnly`, `Secure`, `SameSite=Lax` і `Path=/api`.
3. Надсилайте cookie із запитами до захищених операцій. Для виходу викличте
   `POST /api/auth/logout`; операція ідемпотентна і може бути викликана без
   активної сесії.

У браузері використовуйте same-origin запити з credentials. Через атрибут
`Secure` cookie слід надсилати через HTTPS; loopback-адреси на кшталт
`127.0.0.1` підтримуються для локальної розробки.

## Операції

| Метод | Шлях | Опис | Сесія |
| --- | --- | --- | --- |
| `POST` | `/api/auth/register` | Створити обліковий запис | Ні |
| `POST` | `/api/auth/login` | Увійти й отримати cookie сесії | Ні |
| `POST` | `/api/auth/logout` | Завершити сесію | Не обов’язкова |
| `GET` | `/api/books?page={page}` | Отримати сторінку бібліотеки | Так |
| `POST` | `/api/books` | Створити книгу | Так |
| `GET` | `/api/books/{bookId}` | Отримати книгу | Так |
| `PATCH` | `/api/books/{bookId}` | Частково оновити книгу | Так |
| `DELETE` | `/api/books/{bookId}` | Видалити книгу та її записи | Так |
| `GET` | `/api/books/{bookId}/reading-records` | Отримати записи книги | Так |
| `POST` | `/api/books/{bookId}/reading-records` | Додати запис читання | Так |
| `PATCH` | `/api/reading-records/{recordId}` | Змінити діапазон запису | Так |
| `DELETE` | `/api/reading-records/{recordId}` | Видалити запис читання | Так |
| `GET` | `/api/reading-goals` | Отримати тижневу й місячну цілі | Так |
| `PUT` | `/api/reading-goals/{period}` | Створити або змінити ціль (`week` чи `month`) | Так |
| `DELETE` | `/api/reading-goals/{period}` | Прибрати ціль | Так |
| `GET` | `/api/statistics?period={period}&date={date}` | Отримати статистику (`week`, `month` чи `year`) | Так |

`page` починається з 1; розмір сторінки бібліотеки — 16 книг. `date` для
статистики задається як `YYYY-MM-DD`; якщо параметри статистики не передані,
повертається поточний тиждень. Тиждень починається в понеділок.

## Формат і правила даних

- Тіла запитів і успішні відповіді використовують JSON. Більшість успішних
  відповідей містить ресурс у полі `data`; операції видалення повертають
  `204 No Content`.
- Помилки повертаються як `application/problem+json` із полями `type`, `title`,
  `status`, `code`, `detail`, `instance` та, за потреби, `errors`.
- Дати є календарними датами `YYYY-MM-DD` у часовому поясі `Europe/Kyiv`.
- Власник даних визначається за сесією. Клієнт не передає `ownerId`; ресурси
  іншого користувача недоступні.
- Статус книги, дата запису читання та кількість прочитаних сторінок
  обчислюються сервером. `PATCH` змінює лише передані дозволені поля.

Типові статуси: `400` — некоректний JSON або параметр, `401` — потрібна
автентифікація, `404` — ресурс відсутній або належить іншому користувачеві,
`409` — конфлікт стану або зайнята пошта, `422` — помилка валідації, `500` —
непередбачена серверна помилка. Операційні винятки та точні тіла відповідей
визначені в OpenAPI.
