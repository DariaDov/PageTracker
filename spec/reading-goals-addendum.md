# Проєкт адендуму до SRS: цілі читання

**Базова специфікація:** `specification.md`, версія 1.0
**Тікет:** ADD-02 — «Цілі читання»
**Статус:** адендум схвалено на SPEC-ADDENDUM-GATE-02; артефакти синхронізовано
**Дата підготовки:** 2026-11-13

Цей документ визначає одну нову можливість поза межами SRS v1.0. Він не змінює затверджену специфікацію чи реалізацію; контракт OpenAPI синхронізується після схвалення людиною на SPEC-ADDENDUM-GATE-02.

## 1. Мета та межі

Користувач може встановити повторювану ціль прочитаних сторінок на тиждень та/або місяць і бачити прогрес для поточного календарного періоду. Тижнева й місячна цілі налаштовуються незалежно.

До цього розширення не входять річні цілі, нагадування, історія попередніх значень цілей, соціальні функції або автоматична зміна цілі.

## 2. Нормативні нові вимоги

| ID | Вимога |
| --- | --- |
| REQ-F-044 | Автентифікований користувач може незалежно задати, переглянути, змінити або прибрати повторювану ціль у цілих сторінках на тиждень та/або місяць. Значення має бути цілим числом не менше 1. Неналаштована ціль відсутня. Налаштування зберігається між сесіями та застосовується до кожного наступного періоду відповідного типу, доки користувач його не змінить або не прибере. |
| REQ-F-045 | Для поточного тижня або місяця система показує прогрес цілі за сумою `pagesRead` усіх записів поточного користувача в межах календарного періоду за `Europe/Kyiv`: ціль, прочитану кількість, залишок (мінімум 0), відсоток виконання та ознаку досягнення. Відсоток може перевищувати 100%. Прогрес враховує актуальний стан записів після створення, редагування, видалення запису чи книги. Якщо ціль не налаштована, блок прогресу не показується. |
| REQ-I-020 | На сторінці статистики користувач може переглянути прогрес поточної тижневої та/або місячної цілі, задати чи змінити ціль і прибрати її. Елементи, підказки та повідомлення відображаються українською. |
| REQ-NF-010 | Зміна або видалення цілі є атомарною: після технічної помилки збережене значення залишається попереднім, а часткова зміна не спостерігається. |

REQ-F-044 і REQ-F-045 є новими функціональними вимогами. Вони не переозначують поточні вимоги статистики, а доповнюють їх окремим поданням цільового темпу.

## 3. API-контракт

Наведений контракт є частиною схваленого розширення ADD-02 і відображений у OpenAPI 3.1 YAML та JSON.

### 3.1 Керування налаштованими цілями

- `GET /api/reading-goals` повертає активні налаштування користувача у звичайній оболонці `data`:
  - `week`: `{ "targetPages": integer }` або `null`;
  - `month`: `{ "targetPages": integer }` або `null`.
- `PUT /api/reading-goals/{period}` створює або замінює ціль для `week` чи `month`; тіло має містити лише `targetPages`, ціле число від 1 до 2 147 483 647. Успішна операція повертає `200` з установленою ціллю в `data`.
- `DELETE /api/reading-goals/{period}` прибирає відповідну ціль та повертає `204`, навіть якщо ціль уже була відсутня.
- Усі три операції вимагають активної сесії; чужі налаштування недоступні.
- Некоректне JSON-тіло відхиляється з `400`; невідомий `period`, відсутнє/невідоме поле або неприпустиме значення відхиляється з `422` за чинним форматом Problem Details API.

### 3.2 Подання прогресу

Для запиту поточного тижня або місяця `GET /api/statistics` доповнюється необов’язковим полем `goalProgress`, якщо для відповідного періоду налаштована ціль:

```json
{
  "targetPages": 100,
  "pagesRead": 40,
  "remainingPages": 60,
  "percentage": 40,
  "achieved": false
}
```

`pagesRead` обчислюється з актуальних записів власника за межами відповідного календарного періоду в `Europe/Kyiv`. `remainingPages` дорівнює `max(targetPages - pagesRead, 0)`. `percentage` дорівнює `pagesRead / targetPages * 100` без обмеження 100. `achieved` істинне, якщо `pagesRead >= targetPages`. Якщо період не поточний, тип періоду — `year` або ціль не налаштована, `goalProgress` не повертається.

Ця пропозиція не змінює формулу `averagePagesPerDay`, `daysCounted` чи інші наявні поля статистики.

## 4. Критерії приймання

1. Після встановлення тижневої цілі `GET /api/reading-goals` повертає її; після перезапуску сховища та повторного входу налаштування зберігається.
2. Тижнева та місячна цілі можна встановлювати, змінювати й видаляти незалежно; видалення однієї не змінює іншу.
3. Нуль, від'ємне, дробове, рядкове або більше `2 147 483 647` значення не зберігається та повертає узгоджену помилку валідації.
4. Неавтентифіковані запити до цілей відхиляються; користувач не може прочитати чи змінити налаштування іншого користувача.
5. Поточна цільова статистика рахує записи обох меж періоду включно за календарною датою `Europe/Kyiv`; майбутні записи не включаються.
6. Прогрес коректно показує нуль сторінок, точне досягнення, перевищення 100%, залишок 0 і відсутність цілі.
7. Редагування/видалення запису або видалення книги змінює наступний розрахунок прогресу без застарілого кешу.
8. На переході до нового тижня/місяця прогрес починається з записів нового періоду, а повторювана ціль лишається налаштованою.
9. Інтерфейс статистики дозволяє встановити/змінити/прибрати обидві цілі та показує прочитане, ціль, залишок, відсоток і досягнення українською.
10. Помилка сховища під час зміни або видалення цілі не залишає часткового стану та повертає безпечну стандартну помилку API.
11. Усі наявні тести проходять; нові тести створюються до реалізації поведінки (TDD). OpenAPI YAML і JSON, API-сценарії та traceability синхронізовані з затвердженим контрактом.
