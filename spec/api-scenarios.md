# Сценарії приймання REST API PageTracker

Сценарії визначають очікувану поведінку API для позитивних і негативних випадків. Вони доповнюють SRS, не змінюючи його правил; транспортні уточнення відповідають погодженому [адендуму API](./api-contract-addendum.md). URI наведено з базовим префіксом `/api`. Усі відповіді з помилками мають єдину модель Problem Details; наведені `code` та HTTP-статуси відповідають OpenAPI-контракту.

## Передумови та тестові дані

- Якщо сценарій не перевіряє автентифікацію, запит виконується від імені автентифікованого користувача A.
- Користувач B — інший автентифікований користувач, ізольований від A.
- Нова книга `Book A` належить A, має 100 сторінок, статус `розпочати`, без записів і рейтингу.
- `Book B` та її записи належать лише користувачу B.
- Під «не змінює дані» мається на увазі, що після відхиленого запиту стан ресурсу та похідна статистика залишаються незмінними.

## Позитивні сценарії

```gherkin
Feature: Позитивні сценарії REST API

  Scenario: Реєстрація створює обліковий запис без входу
    Given пошта "Reader@example.com" ще не зареєстрована
    When клієнт надсилає POST /api/auth/register з непорожніми email і password
    Then API повертає 201 Created з публічним ресурсом user
    And відповідь не містить пароля чи cookie сесії
    And наступний запит до захищеного ресурсу без входу повертає 401
    And запит не авторизує користувача автоматично

  Scenario: Пошта розрізняє регістр
    Given пошта "Reader@example.com" вже зареєстрована
    When реєструється "reader@example.com"
    Then API створює окремий обліковий запис і повертає 201 Created

  Scenario: Вхід встановлює сесію
    Given існує обліковий запис із коректною поштою та паролем
    When клієнт надсилає POST /api/auth/login з цими обліковими даними
    Then API повертає 200 OK з публічним ресурсом user
    And встановлює HttpOnly, Secure cookie pt_session
    And запити з цією сесією до захищених ресурсів дозволені

  Scenario: Вихід завершує сесію
    Given користувач A має активну сесію
    When клієнт надсилає POST /api/auth/logout
    Then API повертає 204 No Content і очищує cookie pt_session
    And подальший запит до захищеного ресурсу без повторного входу повертає 401

  Scenario: Отримання бібліотеки повертає лише книги власника
    Given користувачі A і B мають власні книги
    When A надсилає GET /api/books?page=1
    Then API повертає 200 OK з книгами лише A
    And повертає не більше 16 книг і метадані пагінації

  Scenario: Створення книги встановлює початковий стан
    Given користувач A має активну сесію
    When A створює книгу з назвою, автором і цілим totalPages не менше 1
    Then API повертає 201 Created
    And нова книга має статус "розпочати" та rating null

  Scenario: Отримання книги повертає її деталі
    Given Book A належить користувачу A
    When A надсилає GET /api/books/{bookId} для Book A
    Then API повертає 200 OK із назвою, автором, кількістю сторінок, статусом і рейтингом

  Scenario: Редагування метаданих книги
    Given Book A існує
    When A надсилає PATCH /api/books/{bookId} з новою назвою та автором
    Then API повертає 200 OK з оновленою книгою
    And статус книги лишається керованим сервером

  Scenario: Зміна кількості сторінок книги без записів
    Given Book A ще не має записів читання
    When A надсилає PATCH /api/books/{bookId} з totalPages 120
    Then API повертає 200 OK
    And кількість сторінок книги стає 120

  Scenario: Оцінювання завершеної книги
    Given книга користувача A має статус "прочитано"
    When A надсилає PATCH /api/books/{bookId} з рейтингом 5
    Then API повертає 200 OK
    And книга має рейтинг 5

  Scenario: Видалення книги видаляє її записи та внесок у статистику
    Given книга користувача A має записи читання
    When A надсилає DELETE /api/books/{bookId}
    Then API повертає 204 No Content
    And книга та її записи більше не повертаються API
    And подальша статистика A не враховує видалену книгу

  Scenario: Перший запис починається зі сторінки 1
    Given Book A має статус "розпочати" і не має записів
    When A створює запис 1–10 через POST /api/books/{bookId}/reading-records
    Then API повертає 201 Created
    And запис містить startPage 1, endPage 10 і pagesRead 10
    And дата встановлена сервером у часовому поясі Europe/Kyiv
    And статус книги змінюється на "читається"

  Scenario: Дозволені кілька записів за одну дату
    Given Book A має послідовний запис сторінок 1–10 за сьогодні
    When A створює запис сторінок 11–20 за ту саму поточну дату
    Then API повертає 201 Created
    And записи зберігаються окремо

  Scenario: Допустимий одно-сторінковий запис завершує книгу
    Given Book A має статус "читається" і останній запис закінчується на сторінці 99
    When A створює запис сторінок 100–100
    Then API повертає 201 Created
    And pagesRead дорівнює 1
    And статус книги стає "прочитано"

  Scenario: Отримання записів повертає визначений порядок
    Given Book A має кілька записів за різні дати та кілька записів за одну дату
    When A надсилає GET /api/books/{bookId}/reading-records
    Then API повертає 200 OK без пагінації
    And записи впорядковані за датою зростання, а для однакової дати — за startPage зростання

  Scenario: Редагування запису перераховує похідні дані
    Given Book A має статус "читається" і запис 1–10
    When A змінює кінцеву сторінку цього запису на 20
    Then API повертає 200 OK із pagesRead 20
    And статистика враховує оновлену кількість сторінок

  Scenario: Видалення останнього незавершеного запису повертає початковий статус
    Given Book A має статус "читається" і лише один запис 1–10
    When A надсилає DELETE /api/reading-records/{recordId}
    Then API повертає 204 No Content
    And статус Book A стає "розпочати"

  Scenario: Обчислення статистики за поточний тиждень
    Given за поточний тиждень є записи читання кількох книг користувача A
    When A надсилає GET /api/statistics без параметрів
    Then API повертає 200 OK з поточним тижнем від понеділка до неділі
    And pagesReadTotal містить суму сторінок усіх записів у періоді
    And daysCounted не враховує майбутні дні періоду
    And averagePagesPerDay дорівнює сумі, поділеній на daysCounted і округленій до найближчого цілого

  Scenario: Округлення середнього 0,5 вгору
    Given сума сторінок ділиться на daysCounted із результатом, дробова частина якого дорівнює 0,5
    When A запитує статистику цього періоду
    Then averagePagesPerDay округлюється вгору до найближчого цілого

  Scenario: Вибір минулого місяця
    Given користувач A має записи у вибраному минулому місяці
    When A надсилає GET /api/statistics?period=month&date={дата_місяця}
    Then API повертає межі саме цього календарного місяця
    And статистика враховує записи A у цьому місяці
```

## Негативні сценарії

```gherkin
Feature: Негативні сценарії REST API

  Scenario: Реєстрація з порожнім або пробільним полем
    Given запит містить відсутню пошту або пошту чи пароль лише з пробілів
    When клієнт надсилає POST /api/auth/register
    Then API повертає 422 Unprocessable Content з code VALIDATION_ERROR
    And тіло відповідає спільній моделі Problem Details
    And обліковий запис не створюється

  Scenario: Реєстрація із зайнятою поштою
    Given пошта вже зареєстрована з урахуванням регістру
    When клієнт надсилає POST /api/auth/register з тією самою поштою
    Then API повертає 409 Conflict з code EMAIL_ALREADY_EXISTS
    And detail дорівнює "Неправильні дані"
    And пароль і внутрішні дані облікового запису не розкриваються

  Scenario: Вхід із неправильними обліковими даними
    Given пошта не існує або пароль неправильний
    When клієнт надсилає POST /api/auth/login
    Then API повертає 401 Unauthorized з code INVALID_CREDENTIALS
    And в обох випадках detail дорівнює "Неправильні дані"
    And сесійна cookie не встановлюється

  Scenario: Захищена операція без сесії
    Given клієнт не має активної сесії
    When клієнт запитує бібліотеку або статистику
    Then API повертає 401 Unauthorized з code AUTH_REQUIRED
    And жодні приватні дані не повертаються

  Scenario: Доступ до чужої книги чи запису
    Given Book B або її запис належать користувачу B
    When користувач A запитує, змінює або видаляє цей ресурс
    Then API повертає 404 Not Found з code NOT_FOUND
    And відповідь не розрізняє відсутній і чужий ресурс
    And дані B не змінюються

  Scenario: Створення книги з невалідними даними
    Given назва чи автор порожні/лише з пробілів або totalPages не є цілим числом від 1
    When A надсилає POST /api/books
    Then API повертає 422 Unprocessable Content з code VALIDATION_ERROR
    And detail або помилка відповідного поля містить "заповніть дані"
    And книга не створюється

  Scenario: Некоректний номер сторінки бібліотеки
    Given query-параметр page не є цілим числом від 1
    When A надсилає GET /api/books?page={invalid}
    Then API повертає 400 Bad Request з code INVALID_PARAMETER
    And стан бібліотеки не змінюється

  Scenario: Зміна кількості сторінок після початку читання
    Given Book A вже має запис читання
    When A надсилає PATCH /api/books/{bookId} зі зміненим totalPages
    Then API повертає 409 Conflict з code STATE_CONFLICT
    And кількість сторінок і записи книги не змінюються

  Scenario: Рейтинг недоступний для незавершеної книги
    Given Book A має статус "розпочати" або "читається"
    When A надсилає PATCH /api/books/{bookId} з рейтингом від 1 до 5
    Then API повертає 409 Conflict з code STATE_CONFLICT
    And рейтинг книги не змінюється

  Scenario: Рейтинг поза діапазоном
    Given книга має статус "прочитано"
    When A надсилає рейтинг менше 1, більше 5 або не ціле число
    Then API повертає 422 Unprocessable Content з code VALIDATION_ERROR
    And рейтинг книги не змінюється

  Scenario: Створення запису з неповною формою
    Given запит не містить startPage або endPage
    When A надсилає POST /api/books/{bookId}/reading-records
    Then API повертає 422 Unprocessable Content з code VALIDATION_ERROR
    And запис не створюється

  Scenario: Кінцева сторінка менша за початкову
    Given Book A має статус "розпочати"
    When A створює запис, де endPage менша за startPage
    Then API повертає 422 Unprocessable Content з code VALIDATION_ERROR
    And повідомлення відповідає SRS: "Кінцева сторінка, менша за початкову"
    And запис не створюється

  Scenario: Сторінки не є цілими або виходять за межі книги
    Given Book A має 100 сторінок
    When A надсилає запис із нецілою межею або сторінкою 0 чи 101
    Then API повертає 422 Unprocessable Content з code VALIDATION_ERROR
    And повідомлення відповідає SRS: "Будь ласка, змініть сторінку"
    And запис не створюється

  Scenario: Діапазон перетинає вже прочитані сторінки
    Given Book A має запис 1–10
    When A створює або редагує діапазон, що перетинається зі сторінками 1–10
    Then API повертає 409 Conflict з code STATE_CONFLICT
    And повідомлення відповідає SRS: "Ці сторінки вже прочитані"
    And попередній стан записів збережено

  Scenario: Новий запис пропускає сторінки
    Given Book A має послідовні записи до сторінки 10
    When A створює запис, що починається зі сторінки 12
    Then API повертає 409 Conflict з code STATE_CONFLICT
    And повідомлення відповідає SRS: "Відсутні сторінки"
    And запис не створюється

  Scenario: Запис створюється для завершеної книги
    Given Book A має статус "прочитано"
    When A надсилає POST /api/books/{bookId}/reading-records
    Then API повертає 409 Conflict з code STATE_CONFLICT
    And книга та її записи не змінюються

  Scenario: Редагування або видалення запису завершеної книги
    Given книга має статус "прочитано"
    When A намагається змінити або видалити один із її записів
    Then API повертає 409 Conflict з code STATE_CONFLICT
    And статус "прочитано" та записи лишаються незмінними

  Scenario: Видалення проміжного запису утворило б розрив
    Given Book A має записи 1–10, 11–20 та 21–30
    When A видаляє запис 11–20
    Then API повертає 409 Conflict з code STATE_CONFLICT
    And повідомлення відповідає SRS: "Видалення заборонене"
    And усі записи залишаються на місці

  Scenario: Невалідний PATCH не зберігає частину змін
    Given Book A має записи 1–10 та 11–20
    When A надсилає PATCH, де одна межа утворює перетин або пропуск
    Then API відхиляє весь запит як 409 Conflict
    And жодна межа та похідна статистика не змінюються

  Scenario: Непідтримуваний період або некоректна дата
    Given query-параметр period не є week, month або year, або date має некоректний формат
    When A надсилає GET /api/statistics
    Then API повертає 400 Bad Request з code INVALID_PARAMETER
    And статистичні дані не змінюються

  Scenario: Помилка збереження книги чи запису
    Given під час операції збереження виникає технічна помилка
    When A створює або змінює книгу чи запис
    Then API повертає 500 Internal Server Error з code INTERNAL_ERROR
    And detail дорівнює "Помилка"
    And жодні часткові зміни не зберігаються

  Scenario: Технічна помилка отримання статистики
    Given під час обчислення статистики виникає технічна помилка
    When A надсилає GET /api/statistics
    Then API повертає 500 Internal Server Error з code INTERNAL_ERROR
    And detail дорівнює "Помилка"
    And відповідь не містить внутрішніх подробиць помилки
```

## Відповідність API-операціям та REQ-ID

| API operation | Позитивні сценарії | Негативні сценарії | REQ-ID |
| --- | --- | --- | --- |
| `POST /api/auth/register` | Реєстрація без входу; регістр пошти | Порожні поля; зайнята пошта | REQ-F-019, REQ-F-021…023, REQ-F-030, REQ-F-041, REQ-F-042, REQ-NF-003 |
| `POST /api/auth/login` | Успішний вхід | Неправильні облікові дані | REQ-F-020, REQ-F-030, REQ-I-009, REQ-NF-003, REQ-NF-005 |
| `POST /api/auth/logout` | Завершення сесії | Доступ до захищеної операції після виходу | REQ-F-029, REQ-NF-005 |
| `GET /api/books` | Власна бібліотека та пагінація | Немає сесії; некоректний номер сторінки | REQ-F-001, REQ-I-004, REQ-I-015, REQ-I-016, REQ-NF-002, REQ-NF-007 |
| `POST /api/books` | Створення книги з початковим статусом | Невалідні назва, автор чи кількість сторінок | REQ-F-001, REQ-F-002, REQ-F-004, REQ-F-024, REQ-F-026, REQ-F-027, REQ-F-042, REQ-I-010, REQ-I-011, REQ-NF-006, REQ-NF-007 |
| `GET /api/books/{bookId}` | Отримання деталей | Чужа або відсутня книга | REQ-F-001, REQ-F-005, REQ-I-003 |
| `PATCH /api/books/{bookId}` | Редагування метаданих, сторінок до першого запису, рейтинг завершеної книги | Сторінки після запису; рейтинг незавершеної книги або поза межами | REQ-F-001, REQ-F-005, REQ-F-013, REQ-F-028, REQ-F-042, REQ-I-018, REQ-NF-006 |
| `DELETE /api/books/{bookId}` | Видалення книги та каскадних записів | Чужа або відсутня книга | REQ-F-001, REQ-F-014, REQ-F-039, REQ-I-017, REQ-NF-006 |
| `GET /api/books/{bookId}/reading-records` | Впорядкований список без пагінації | Чужа або відсутня книга | REQ-F-001, REQ-F-003, REQ-F-007, REQ-I-006 |
| `POST /api/books/{bookId}/reading-records` | Перший запис, кілька записів на дату, завершення книги | Неповні/некоректні межі, перетин, пропуск, завершена книга | REQ-F-001, REQ-F-003, REQ-F-006…010, REQ-F-025, REQ-F-035, REQ-F-036, REQ-F-042, REQ-F-043, REQ-I-007, REQ-I-008, REQ-I-019, REQ-NF-002, REQ-NF-006, REQ-NF-007 |
| `PATCH /api/reading-records/{recordId}` | Оновлення діапазону та перерахунок статистики | Перетин, пропуск, неправильні межі, завершена книга, атомарна відмова | REQ-F-001, REQ-F-006, REQ-F-008…011, REQ-F-032, REQ-F-034, REQ-F-036, REQ-F-039, REQ-I-013, REQ-NF-006 |
| `DELETE /api/reading-records/{recordId}` | Видалення останнього незавершеного запису | Заборона видалення завершеного чи проміжного запису | REQ-F-001, REQ-F-031, REQ-F-033, REQ-F-037, REQ-F-039, REQ-I-013, REQ-NF-006 |
| `GET /api/statistics` | Поточний тиждень, минулий період, округлення, кількість днів | Некоректні параметри; технічна помилка | REQ-F-001, REQ-F-015…018, REQ-F-038…040, REQ-I-005, REQ-NF-002 |
