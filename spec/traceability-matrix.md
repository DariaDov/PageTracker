# Матриця простежуваності PageTracker

**Версія:** 0.6
**Призначення:** для вимог базової SRS та схвалених адендумів пов’язати критерій прийняття, тікет, тест, модуль коду, конкретний елемент інтерфейсу й розділ документації. REST API додатково простежується до операцій OpenAPI, контрактних перевірок і виконуваних тестів сервера. У колонці «Тікет» наведено повний ланцюжок робіт: `TEST → FEAT → VER → VAL → GATE`; `GATE` є лише людським рішенням про перехід.

Позначка `—` у BDD означає, що окремий сценарій не виділено понад критерій прийняття. Для непридатного UI у відповідній колонці наведено причину.

## Підсумкова контрольна точка лабораторної роботи

Докази й рішення зафіксовано в [підсумковому журналі](../logs/LAB-final-checkpoint.md). Людина обрала **GO** після ознайомлення з рекомендацією **REVISE** та відкритими обмеженнями; це не змінює схвалений **GATE-14** для адендуму «Цілі читання».

Поточне оновлення доказів: для всіх 74 вимог SRS та схваленого адендуму є критерій, тікет, тест, код, UI-елемент або явне обґрунтування його непридатності, і посилання на розділ документації; додано браузерний UI та виконувані тести API-сервера. Незалежний PostgreSQL-прогін досі має 5 пропусків без `TEST_DATABASE_URL`; це обмежує лише висновки про реальне PostgreSQL-збереження/продуктивність, а не результати тестів логіки API на контрольованому сховищі. Історичне людське **GO** у [підсумковому журналі](../logs/LAB-final-checkpoint.md) не змінено; нові докази не є автоматичним рішенням людини щодо Gate.
