# Матриця простежуваності PageTracker

**Версія:** 0.3
**Призначення:** зв’язати вимоги SRS з критеріями прийняття, BDD-сценаріями та плановими тікетами; REST API — додатково з операціями OpenAPI та доказами mock-перевірки. У колонці «Тікет» наведено повний ланцюжок робіт: `TEST → FEAT → VER → VAL → GATE`; `GATE` є лише людським рішенням про перехід.

Позначка `—` у BDD означає, що окремий сценарій ще не сформовано.

## REST API: простежуваність та докази API-GATE

Погоджені уточнення API-CL зафіксовано в [адендумі REST API](./api-contract-addendum.md). Таблиця операцій нижче є наскрізною простежуваністю кожної API operation до REQ-ID SRS, сценаріїв і OpenAPI; наступна таблиця пов’язує погоджені API-CL із gate-критеріями. Статус mock показує лише фактично перевірену поведінку. Сам факт наявності прикладу відповіді або примусового вибору прикладу через `Prefer` не доводить виконання правила предметної області.
